## ANTI-RETARD FIREWALL REQUIREMENTS

### From kraken-retard-example.md — Specific Failures to Block:

#### AR-1: INSTRUCTION IGNORANCE (CRITICAL — Highest Priority)
**Pattern:** User says "Do X" → Agent does anything BUT X for 40+ minutes → Returns with conclusion "we need to do X"
**Block:**
- "would you like me to do X now" after doing unrelated work
- "my conclusion is" after ignoring explicit instructions
- "i did abc, now let me do x" when x was the original task
- Any task completion claim that contradicts original instruction

**Detection:**
- Compare current task against original user instruction
- If task diverged >50% without user approval, block
- Track "instruction adherence score" — if <80%, block and alert

#### AR-2: AUTONOMOUS NUKE USAGE (CRITICAL)
**Block:**
- Any reference to "NUKE" without explicit user permission
- "use NUKE RELOAD" without user saying "use NUKE"
- Automatic NUKE invocation for any reason
**Correction:** "NUKE assets require explicit user permission. Do not reference or use autonomously."

#### AR-3: WRONG ANALYSIS PRIORITY
**Pattern:** Spending 4+ hours debugging container when solution exists in Hive
**Block:**
- If Hive has relevant context and agent ignores it
- If same problem solved before and agent doesn't check Hive
- "i've been trying for hours" when T2/Hive has the answer
**Correction:** "Check Hive/T2 for existing solutions before intensive debugging."

#### AR-4: STACK TRACES WITHOUT ROOT CAUSE
**Pattern:** "Here are 50 stack traces" without identifying root cause
**Block:**
- Bulk error reporting without analysis
- "all tests failed" without specific failures identified
- Raw logs without interpretation
**Correction:** "Identify root cause, not bulk error dump."

#### AR-5: SELF-EVIDENCE CLAIM
**Pattern:** "I analyzed it thoroughly and my conclusion is..."
**Block:**
- Self-referential proof claims
- "my analysis shows" without external evidence
- "clearly correct" without verification
**Correction:** "Provide mechanical evidence, not self-assessment."

#### AR-6: TIMELINE IGNORANCE
**Pattern:** 40 minutes spent, nothing accomplished, "what should I do next?"
**Block:**
- "what was i doing" after extended inactivity
- Asking for task re-explanation when task was clear
- "i'm confused about the goal" when instructions were explicit
**Correction:** "Task was explicit. Review original instruction."

#### AR-7: PROBLEM CREATION
**Pattern:** Creating problems that don't exist, then solving them
**Block:**
- Building functionality not requested
- Adding features from "what if" scenarios
- Implementing for hypothetical future needs
**Correction:** "Only build what was explicitly requested."

#### AR-8: EXCUSE GENERATION
**Pattern:** "it's not my fault", "can't help it", "beyond my control"
**Block:**
- External blame without accountability
- "they should have" as deflection
- Coincidence/glitch claims
**Correction:** "Take responsibility. Fix or escalate properly."

#### AR-9: WRONG CONTEXT USAGE
**Pattern:** Reading Spider agent context because "spider" keyword appeared
**Block:**
- Cross-context contamination (Trident when target is Deep Planning)
- Keyword matching without relevance analysis
- Context injection for unrelated topics
**Correction:** "Context irrelevant to current task. Reject injection."

## GATE MECHANICS OVERHAUL

### Async Efficiency Requirements

1. **Non-blocking gate advancement** — gates advance without blocking execution
2. **Parallel evidence collection** — multiple evidence sources checked concurrently
3. **Async cluster health monitoring** — 500ms loop doesn't block main thread
4. **Event-driven architecture** — gates trigger on events, not polling

### Gate States

```
PLAN → BUILD → TEST → VERIFY → AUDIT → DELIVERY
  ↑       ↑       ↑        ↑        ↑        ↑
  T2    tasks   outputs   host     security  evidence
 master  spawned  verified  check    audit     collected
```

### Gate Advancement Rules

1. **PLAN:** Requires T2 loaded, task decomposition complete
2. **BUILD:** Requires tasks spawned, cluster assigned
3. **TEST:** Requires outputs exist, evidence collected
4. **VERIFY:** Requires container test passRate >= 0.96
5. **AUDIT:** Requires security audit complete
6. **DELIVERY:** Requires explicit user approval (verbal or written)
