## What Happened

## Key Problem Discovered

**Semantic search WORKS but content fetch FAILS.** Agents get search results but the actual content is not returned.

## Root Cause (THE ACTUAL BUG)

OpenViking stores content in `.upload_HASH.md` files but search returns `.overview.md` (metadata).

Example:
1. Search for "container testing" → returns `container-testing-hardcoded-version-failure.md/.overview.md`
2. Fetch that URI → returns "Directory overview" (metadata, NOT content)
3. Actual content is at `container-testing-hardcoded-version-failure.md/upload_4798da7b2b684ba7b1d617219dbd5aff.md`

**Fix applied to hive-mind-plugin.ts:**
1. When sorting search results, PRIORITIZE `.upload_` files over `.overview.md`
2. For metadata URIs (`.overview.md`, `.abstract.md`), use local fallback which has proper structure
3. Increase search limit to 10 to get more results to filter
- FLAT folder structure
- Glob/read directly - no search
- Clear naming conventions so agents can find files by keyword

## The REAL Context Library Structure (Reference)

```
/Shared Workspace Context/
  - Guardian (Local)/          ← File protection system
  - Kraken Agent/             ← Agent-specific context

      - kraken-context/       ← T2_* operational docs
      - identity/             ← Agent identity files
  - Shark Agent/

  - Hive Mind Plugin/

```

This structure WORKS because:
1. Flat - no nesting hell
2. Named with keywords agents can glob for
3. Read directly - no semantic search dependency
4. Each folder = one topic/domain
